# TL-WR840N v6 + OpenWrt + WireGuard

Набор для сборки OpenWrt 19.07.10 с WireGuard для TP-Link TL-WR840N Ver 6.0 / 6.1 / 6.2 / 6.20 и настройки туннеля.

| Файл | Зачем |
|---|---|
| `.github/workflows/build.yml` | сборка на GitHub (GitHub Actions) |
| `build.sh` | тот же скрипт сборки для своего ПК |
| `wg-setup.sh` | настройка WireGuard на роутере после прошивки |

## Что важно знать заранее

- Официальной поддержки v6 в OpenWrt нет. Основа — неофициальный форк IcedShake (зафиксирован по коммиту). Ветка 19.07 не получает обновлений безопасности с 2022 года.
- Флеш 4 МБ. В прошивке: WireGuard, Wi-Fi, firewall, SSH. Нет веб-интерфейса, IPv6 и менеджера пакетов — иначе не хватит места под настройки.
- LuCI и PPPoE включаются галочками. Если образ получится больше 3,5 МБ, сборка остановится с предупреждением: такой файл шить нельзя, настройки не будут сохраняться.
- Для Ver 6.2/6.20 сборка проверена людьми на форуме OpenWrt. Для 6.0/6.1 — почти не проверялась.
- На форуме есть случаи «кирпича» после прошивки. Подготовьте стоковую прошивку для отката (раздел 4), а на крайний случай — программатор CH341A.
- В исходном форке Wi-Fi включался открытым, без пароля. Здесь это убрано: после прошивки Wi-Fi выключен.

## 1. Сборка

Сборка на GitHub запускается сама при каждом изменении в ветке `main` (правки `.md` не в счёт) и идёт около часа.

Запустить вручную, в том числе с LuCI или PPPoE: вкладка Actions → «TL-WR840N v6 + WireGuard» → Run workflow.

Готовые файлы появляются в ветке [`firmware`](../../tree/firmware) и в разделе Artifacts у запуска. В ветке также лежат `status.txt` (успех или ошибка) и `build-log-tail.txt` (конец лога сборки).

### Сборка на своём ПК (Ubuntu 20.04/22.04 или WSL, 1–3 часа)

```sh
sudo apt update
sudo apt install build-essential file gawk gettext git libncurses5-dev libssl-dev \
  python2 python3 python3-distutils rsync unzip wget xsltproc zlib1g-dev flex bison bzip2 patch time
mkdir -p ~/wr840n && cd ~/wr840n      # в WSL — только в домашней папке, не в /mnt/c
cp /путь/к/build.sh . && chmod +x build.sh
./build.sh                            # или LUCI=1 ./build.sh, PPPOE=1 ./build.sh
```

На Ubuntu 24.04 нет python2, поэтому собирайте в Docker из той же папки:

```sh
docker run --rm -v "$PWD":/w -w /w -e FORCE_UNSAFE_CONFIGURE=1 ubuntu:20.04 bash -c '
  apt-get update && DEBIAN_FRONTEND=noninteractive apt-get install -y build-essential ca-certificates \
  file gawk gettext git libncurses5-dev libssl-dev python2 python3 python3-distutils rsync unzip wget \
  xsltproc zlib1g-dev flex bison bzip2 patch time && bash build.sh'
```

### Что получится

Папка `firmware/`:

- `Ver_6.0_6.1/` — для наклейки Ver 6.0 или 6.1;
- `Ver_6.2_6.20/` — для наклейки Ver 6.2 или 6.20;
- в каждой папке `tp_recovery.bin` (первая прошивка по TFTP) и `sysupgrade.bin`;
- `SHA256SUMS` и `build-info.txt`.

## 2. Прошить по TFTP

1. Посмотрите наклейку снизу роутера и возьмите `tp_recovery.bin` из нужной папки.
2. Запустите TFTP-сервер (Tftpd64 на Windows, tftpd-hpa на Linux) с папкой, где лежит `tp_recovery.bin`.
3. Задайте сетевой карте ПК статический IP 192.168.0.66, маску 255.255.255.0. Кабель — в любой LAN-порт роутера.
4. Выключите роутер, зажмите WPS/Reset и включите питание, держите 5–10 секунд. Роутер сам скачает файл (это видно в логе TFTP) и через 1–2 минуты перезагрузится.
5. Если файл не запрашивается, в Wireshark видно, какой IP и какое имя файла просит роутер.
6. После прошивки переключите ПК на DHCP. Роутер будет на 192.168.1.1, вход — `ssh root@192.168.1.1` (пароля пока нет).

Обновлять уже прошитый роутер проще так же, по TFTP.

## 3. Настроить WireGuard

Обычная схема: роутер на объекте — клиент и сам подключается к серверу WireGuard с белым IP (VPS или офис). Белый IP на объекте не нужен.

1. Откройте `wg-setup.sh` и заполните поля вверху: пароль root, ключ и адрес сервера, адрес роутера в туннеле, новую подсеть LAN.
2. Зайдите `ssh root@192.168.1.1`, вставьте весь текст скрипта и нажмите Enter.
3. Скрипт выведет готовый блок `[Peer]`. Добавьте его на сервер и перезапустите туннель там.
4. Через минуту выполните на роутере `wg show`: должна появиться строка `latest handshake`.

Правило для многих объектов: у каждого своя подсеть LAN (`LAN_IP`, например 192.168.51.1, 192.168.52.1…) и свой адрес в туннеле (`WG_ADDR`: 10.8.0.2, 10.8.0.3…). Иначе сервер не поймёт, куда слать трафик.

Пример сервера на VPS с Ubuntu, файл `/etc/wireguard/wg0.conf`:

```ini
[Interface]
Address = 10.8.0.1/24
ListenPort = 51820
PrivateKey = <приватный ключ сервера>

# объект 1 — блок, который вывел wg-setup.sh
[Peer]
PublicKey = <ключ роутера>
AllowedIPs = 10.8.0.2/32, 192.168.51.0/24

# телефон или ноутбук монтажника
[Peer]
PublicKey = <ключ телефона>
AllowedIPs = 10.8.0.100/32
```

На сервере включите пересылку: `sysctl -w net.ipv4.ip_forward=1` (и пропишите её в `/etc/sysctl.conf`), затем `wg-quick up wg0`. Если на сервере включён ufw, разрешите пересылку wg0 → wg0. В конфиге телефона укажите `AllowedIPs = 10.8.0.0/24, 192.168.51.0/24`.

Процессор у роутера слабый, поэтому для удалённого просмотра используйте субпоток камер.

## 4. Вернуться на стоковую прошивку

1. Скачайте с tp-link.com прошивку для своей ревизии — файл с `up_boot` в названии.
2. Отрежьте у файла первые 512 байт: `dd if=<файл>.bin of=tp_recovery.bin bs=512 skip=1`.
3. Прошейте результат по TFTP так же, как в разделе 2.
